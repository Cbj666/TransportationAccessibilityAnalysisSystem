# 数据字典 — 武汉等时圈项目 v1 冻结数据

生成脚本：`backend/scripts/prepare_dataset.py`（**会清空并重写 `data/processed/v1/`**）
校验脚本：`backend/scripts/verify_dataset.py`
清单文件：`data/processed/v1/manifest.json`（含每个文件的 SHA-256、行数、要素数）

> 本文件放在 `docs/` 而不是数据目录里，因为 `prepare_dataset.py` 每次会重建
> `data/processed/v1/`，放在里面会被删掉。

- 坐标系：全部图层为 **WGS84 / EPSG:4326**（经纬度）。
- 长度计算另用 **EPSG:32650（UTM 50N）** 投影，字段中长度单位统一为**米**。
- 站点 ID 规则：公交 `B-<station_key>`，地铁 `M-<station_id>`；两类节点 ID 前缀不同，不会冲突。
- 时间：`metro_schedule.csv` 的发车间隔为秒；乘车/步行时间不在数据层给定，由算法层按参数计算。

## 2. `stops_bus.csv`（7,823 行）

| 字段 | 类型 | 说明 |
|---|---|---|
| `node_id` | str | 图节点 ID，`B-` + `station_key`（主键） |
| `station_key` | str | 空间站点唯一键：高德站点 ID + 100 m 聚类后缀，解决高德 ID 复用问题 |

| `snap_distance_m` | float | 原坐标到吸附点的距离（米） |
| `snap_quality` | str | `high`（≤80 m）/ `low`（>80 m），低值站不要用于精确步行接驳 |
| `road_fclass` | str | 吸附道路的 OSM 分类 |
| `road_name` | str | 吸附道路名（2,580 个为空） |

| `record_count` | int | 原始站点记录数 |
| `inside_wuhan` | bool | 旧脚本的边界判定（基于早期边界数据） |
| `in_boundary` | bool | 本次对 `wuhan_boundary.geojson` 重算的判定，**以此为准**；7,732 个在城内 |
| `flags` | str | `snap_gt_80m` / `snap_gt_500m` / 空 |

## 4. `edges_bus.csv`（26,248 行）

一行 = 某条线路某个方向上相邻两站，**有向**。

| 字段 | 类型 | 说明 |
|---|---|---|
| `edge_id` | str | 主键，`E-BUS-######` |
| `label` | str | 公共线路标签（如 `10夜行路`），591 条线路的取值空间 |
| `line_id` | str | 高德方向级线路 ID（1,054 个方向有站序） |
| `line_name` | str | 方向全名，如 `10路(武昌火车站综合体--汉口火车站)` |
| `from_sequence` / `to_sequence` | int | 站点在该方向站序中的序号，从 1 开始 |
| `from_station_key` / `to_station_key` | str | 站点空间键，可回连 `stops_bus.csv` |
| `from_station_id` / `to_station_id` | str | 高德原始站点 ID |
| `from_station_name` / `to_station_name` | str | 站名 |
| `distance_m` | float | 两站**球面直线**距离（米） |
| `dist_route_m` | float | 沿线路走向的**沿线距离**（米），由站点投影到线路几何得到 |
| `detour_ratio` | float | `dist_route_m / distance_m`；中位 1.006，均值 1.113 |
| `dist_source` | str | `shape`（沿线可信，26,156 条）/ `crowfly`（几何异常回退，92 条） |
| `leg_gt_3000m` / `leg_gt_5000m` / `leg_gt_10000m` | bool | 长边标记（248 / 69 / 24 条），多为快速、远郊线路 |
| `mode` | str | 固定 `bus` |
| `from_node` / `to_node` | str | 图节点 ID，可直接建图 |

注意：`distance_m` 是直线距离，长期被当作"站间距"使用会低估乘车时间；
**建图时优先用 `dist_route_m`**，`dist_source=crowfly` 的 92 条按直线 × 1.15～1.3 估算。

## 9. `osm_walk_roads.gpkg` → 图层 `walk_roads`（91,203 条，47,051 km）

步行可用路网，已剔除高速/匝道，向外多留 2 km 以保证边界附近连通。

| 字段 | 类型 | 说明 |
|---|---|---|
| `osm_id` | int | OSM 要素 ID |
| `fclass` | str | OSM 道路分类（unclassified / service / residential / footway / …） |
| `name` / `ref` | str | 道路名 / 编号 |
| `oneway` | str | OSM 原始 `B`/`F`/`T` |
| `oneway_walk` | str | `both` / `forward` / `reverse`，**步行可忽略单行的情形由算法层决定** |
| `bridge` / `tunnel` | bool | 是否桥 / 隧道 |
| `layer` | int | OSM 分层，用于立交判定 |
| `walk_group` | str | `foot`（纯步行道 12,396 条）/ `street`（可步行道路 78,807 条） |
| `length_m` | float | 投影长度（米） |
| `in_boundary` | bool | 中点是否落在武汉市界内（64,788 条在城内，其余为缓冲带） |

拓扑质量：91,203 段共有 979,351 个顶点，**98.8% 的顶点属于同一个极大连通子网**（310 个连通分量，多为山地、封闭小区内部路）。可直接端点匹配建图。

## 11. 数据边界与已知缺口（必须写进说明书/PPT）

1. **公交 591/694 条**，缺 103 条（夜行线 17、P 字头郊区 22、区间车 2、远城区）。
   不能说"武汉全部公交"。
2. **POI 只有 1.4 万个**（边界内 1.07 万），OSM 在武汉的 POI 覆盖明显弱于商业地图，
   远城区几乎空白。POI 统计结论只反映 OSM 覆盖度，不能等同于真实商业密度。
   若答辩需要更可信的 POI 密度，需用高德 POI 分类检索补抓（配额 5,000 次/日）。
3. **地铁站是站中心，不是出入口**；精确步行接驳需出入口数据。
4. **时刻是频率级**（工作日/周末 × 发车间隔），没有逐班次 `stop_times`。
5. **步行路网缺人行道、天桥、地下通道细节**，跨江/跨铁路的步行连通性偏乐观。
6. **公交站吸附**：中位 2.9 m，但 472 个站 >80 m（`snap_quality=low`），
   全部 <15 m 到最近可步行道路，接驳可用但几何精度有限。
7. **POI 与站点都在 WGS84**；高德原始 GCJ-02 坐标保留在 `*_gcj02` 字段，**不要混用**。
