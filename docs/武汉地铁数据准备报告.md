例如 1 号线工作日：

```text
06:00–07:30  5 分钟/趟
07:30–08:30  3 分钟/趟
08:30–23:00  5 分钟/趟
```

周末：

```text
06:30–23:00  5 分钟/趟
```

这些数据可以用于：

- 按工作日/周末区分运营；
- 用发车间隔的一半估算平均候车时间；
- 按运营时段过滤不可用线路；
- 做高峰/平峰差异化的公交+地铁等时圈。

注意：这不是逐班次时刻表，没有每一班车在每个站的到发时刻。不能做精确到分钟的班次衔接，只能做频率近似。

## 六、数据质量与限制

1. **线路已更新**  
   高德站数多于 2020 年公共数据，说明线路有延伸或新增站点。应以高德当前站序为准，公共数据作历史对照。

2. **时刻是频率级**  
   有工作日/周末和高峰/平峰发车间隔，但没有逐班次 `stop_times`。

3. **站点中心不等于出入口**  
   地铁站通常有多个出入口，当前每个站只有一个中心点。步行接驳会存在一定误差。

4. **换乘站需要合并**  
   当前按高德站点 ID 统计为 231 个站点；不同线路的换乘站如果不共享 ID，需要在构建网络时按名称和 50–100 米距离合并为换乘节点。

5. **11 号线和阳逻线跨市**  
   部分站点在武汉边界外（如葛店南站），需要在研究区裁剪时保留边界附近节点，或标记为市外站点。

## 七、下一步

1. 将地铁站与公交站按名称和空间距离合并为综合交通站点；
2. 构建地铁相邻站边：
   - 边权 = 站间距离 / 地铁平均速度 + 停站时间；
   - 或直接用线路总距离和站数估算平均站间时间；
3. 构建换乘边：
   - 同站换乘；
   - 公交站与地铁站 100–300 米步行接驳；
4. 用 `metro_schedule.csv` 的发车间隔估算候车时间；
5. 与 591 条公交线路、OSM 步行网络合并，生成公交+地铁+步行等时圈。

## 八、结论

地铁数据已经具备：

- 9 条线路、18 个方向；
- 231 个站点；
- 516 条相邻站边；
- 18 条实际线路几何；
- 56 条工作日/周末、高峰/平峰时刻规则；
- OSM 步行路网吸附结果。

这些数据足以支撑首版“公交 + 地铁 + 步行”的多模式等时圈原型。主要限制是时刻为频率级、站点为站中心而非出入口，以及跨市线路需要在研究区裁剪时单独处理。
