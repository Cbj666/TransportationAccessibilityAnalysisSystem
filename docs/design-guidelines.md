# 界面设计执行准则

本文件是前端（Vue 3 + 百度地图）的设计执行清单，改编自
`distinctive-ai-design` skill（作者 houxin0010，内容提炼自 Anshu Chimala
《How to turn your AI into a world-class designer》），并针对本项目的
**地图为主角、数据要可信**这两个特点做了改写。

原 skill 是给 Codex 用的（`SKILL.md` frontmatter + `agents/openai.yaml` + 校验脚本），
这里只保留能落地的方法、评审提示和清单，去掉 Codex 包装与 E2E 校验流程。

**适用**：新页面视觉方向、重做首页、消除模板感。
**不适用**：改个按钮颜色、修个对齐、补个 loading —— 直接做，不用走全套。

---

## 一、三阶段流程

### 1. 探索：先拓宽，再收敛

- 先读现有页面、组件、品牌约束，明确：**谁在用、主任务是什么、希望什么感受**。
  本项目的主任务永远是"选起点 → 给时间预算 → 看可达范围与统计"。
- 方向没定时，给 **3 个真正不同的概念**。差异要在构图、信息组织、字体、交互隐喻上，
  **不能只换颜色**。
- 用户已经指定方向就照做；允许自主推进时挑最贴合用途的一版，并写明假设。

把选定方向压成一段可执行 brief（模板见第三节），再动手写代码。

> 卡在模板感里时，可以用本地随机源取一个种子做构图灵感：
> `python -c "import secrets; print(secrets.token_hex(48))"`
> 种子只用于探索，不进产品、不进长期记忆。

### 2. 定义：做出完整的设计个性

- 沿用现有技术栈和组件，**先实现承载主任务的那个页面/关键状态**，不要先铺全局样式。
- 颜色、字体、间距、素材、交互一起服务 brief；单独某一项出彩没有意义。
- 需要图片素材时先问"它承担什么叙事"；我们的地图本身就是视觉主体，
  多数情况下不需要装饰图。没有图像生成工具时，用静态占位并说明。
- 不写死模型/服务版本，不把密钥写进代码、日志或仓库。

### 3. 交付：做减法，检查实际用途

- 逐项问：这个元素帮助用户**理解、操作还是感受**？删掉无用的说明、重复标签、
  装饰容器、抢注意力的动效。
- 渐变、发光、卡片、不对称布局不是原罪；**模板感来自没有意图**，不来自某个样式。
- 原生控件够用就用原生控件（滑块、下拉、开关）。
- 在真实运行环境验证主操作，以及变化涉及的状态。

## 二、本项目的设计约束

这些是从项目性质推出来的硬约束，先于个人偏好：

1. **地图是主角。** 面板、图例、工具栏是浮层；不要让大面积渐变/大卡片压住地图。
   默认视野要能看到整个武汉，而不是挤在汉口一角。
2. **三档配色必须与产出物一致。** 报告和 PPT 里已固定：
   `15 min #2b8cbe` / `30 min #fec44f` / `45 min #d7301f`。
   UI 图例、图表、导出图沿用同一组，不要另起一套。
3. **数据口径要可见。** 界面上必须能找到："公交 591/694 条""POI 来自 OSM（覆盖偏弱）"
   "时刻为频率级近似"。这不是免责声明，是让结论可被正确解读的设计元素。
4. **数字要对齐。** 面积（km²）、站点数、POI 数用 `font-variant-numeric: tabular-nums`，
   否则面板里的数字会随刷新跳动。
5. **坐标系转换只做一次。** 后端出 WGS84，前端转 BD-09 给百度地图；
   不要在多个组件里各转一遍，否则等时圈和站点会错位几百米。
6. **中文排版。** 字体优先 `Microsoft YaHei` / `Noto Sans SC`；行高 ≥1.6；
   地图标注字号小于面板正文一档，避免抢层级。
7. **一个页面只回答一个问题。** 等时圈页面回答"这里 30 分钟能到哪"；
   对比页面回答"这两个点哪个更合适"。不要把两者塞进同一屏。

已填写的一版（可作为起点，允许推翻）：

```text
用户与主任务：做区位比较的人（课程/答辩场景），选一个起点、给 15/30/45 分钟预算，
              看清可达范围、范围内有多少 POI 和站点。
目标感受：可信、克制、有空间感 —— 像一张会说话的地图，而不是一个后台管理面板。
核心视觉隐喻：等时圈是"涟漪"：三档时间由内向外扩散，颜色由冷到暖。
构图与信息层级：地图占 70% 以上；左侧窄面板放起点与预算；右下角浮层放统计；
                  三档图例常驻但低调。
色彩与字体：地图底图降饱和；三档固定色；面板用近白底 + 深灰字；
              中文 Microsoft YaHei，数字 tabular-nums。
关键交互：拖动起点即时重算（防抖 300ms）、预算滑块、图层开关、点击站点看线路。
要避免：全屏渐变、玻璃拟态、四个大 KPI 卡片并排、无意义的图标墙、满屏阴影。
第一版最小范围：单起点 + 三档等时圈 + POI/站点计数 + 图例。对比页下一版再做。
```

## 四、用真实截图评审

**没有截图就不算验证过。** 不要凭代码宣称好看。

### 1. 截图（本仓库可直接用 Edge 无头模式）

```powershell
# 先启动前端 dev server（例如 5173），再截两个尺寸
$edge = "${env:ProgramFiles(x86)}\Microsoft\Edge\Application\msedge.exe"
& $edge --headless=new --disable-gpu --hide-scrollbars `
  --screenshot="data\output\ui\round-1\desktop.png" --window-size=1440,900 `
  "http://127.0.0.1:5173"
& $edge --headless=new --disable-gpu --hide-scrollbars `
  --screenshot="data\output\ui\round-1\mobile.png" --window-size=390,844 `
  "http://127.0.0.1:5173"
```

注意：

- 需要覆盖**主视图 + 与本次改动相关的状态**（如"计算中""已选起点""无结果"）。
- 百度地图底图需要 AK 与网络；没配好时截出来的底图是空白，要在报告中标注"底图未验证"。
- 截图存 `data/output/ui/<round>/`，不要覆盖上一轮。

### 2. 评审（独立上下文，只给图和 brief）

用子代理做评审时，**只给它**：截图、用户/任务说明、brief。**不要给**代码、
实现难度、历史解释、之前的问题清单或目标分数。

评审提示词（每个评审轮都用同一版）：

> 根据截图判断视觉质量。先概括它试图表达的审美，再设想优秀设计团队会如何把这个方向落实。
> 评估整体构图、信息层级、字体、色彩、间距、图像整合和细节一致性，以及主任务是否清楚。
> 重点看：地图是否仍是视觉主体、三档等时圈层级是否一眼可辨、面板信息是否抢戏、
> 数据口径说明是否找得到。指出缺乏用途的装饰、机械重复的布局和削弱个性的选择。
> 给出最多三个最影响效果的问题，每项包含：截图中的位置、具体表现、用户或视觉影响、
> 可执行的调整建议。最后给 0–10 分完成度与简短理由。
> 截图无法证明的交互、性能、无障碍行为一律标注为"未验证"。

没有独立上下文时按同样维度自查，但必须标注 **self-review**。

### 3. 精修

- 每轮只改**最影响效果的 1–3 个问题**，改完重新截图，用同一框架复查。
- **最多两轮**。两轮后没明显收敛就报告剩余缺口，不要无限追分。
- 9/10 只作为内部愿景，**不写进评审提示、不作为上线依据**。

## 五、交付前检查清单

- [ ] 主任务在当前屏幕尺寸下能一次完成，不需要滚动找按钮
- [ ] 三档等时圈颜色与 `#2b8cbe` / `#fec44f` / `#d7301f` 一致
- [ ] 图例、面板、地图标注的字号层级清楚，标注不抢正文
- [ ] 数字用 tabular-nums，刷新不跳动；单位（km²、min、个）齐全
- [ ] 数据口径说明（591/694、POI 来源、频率级时刻）在界面上找得到
- [ ] 空状态、计算中、无结果、跨江断连这四种状态都有交代
- [ ] 1440×900 与 390×844 都不出现横向滚动条
- [ ] 文字对比度足够（正文与背景 ≥ 4.5:1），焦点态可见
- [ ] 关闭动效后主任务仍可完成（`prefers-reduced-motion`）
- [ ] 没有装饰性元素只为了"看起来丰富"

## 六、交付说明怎么写

简短四段，放 PR 描述或 `docs/开发进展-*.md`：

1. 选定的方向与 brief 一句话；
2. 重要删减/修正（对比上一版截图）；
3. 验证证据：截图路径、评审轮次与结论、哪些行为已验证；
4. **尚未验证的部分**（审美评分与功能验证分开报告，不要把分数当验收）。
