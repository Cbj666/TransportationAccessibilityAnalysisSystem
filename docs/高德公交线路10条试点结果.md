# 高德公交线路 10 条试点结果

日期：2026-10-19  
项目：武汉个性化等时圈与区位评估平台  
目的：验证“高德 POI 搜索发现站点 ID → stopid 查线路 ID → lineid 查完整站序”的批量链路

## 一、试点方法

```text
公共公交线路表（694 条）
    → 选取 10 条覆盖中心城区、郊区、环线、远城区的线路
    → place/text 按线路号分页搜索公交站 POI
    → 按地址中的线路号过滤，得到站点 ID
    → bus/stopid 按站点 ID 查询经过线路，得到线路 ID
    → bus/lineid 按线路 ID 查询完整、带站序的站点列表
    → 按公共线路首末站、站名重合度和内外环后缀选择最佳方向
```

请求间隔 2 秒，缓存成功响应，QPS 错误自动退避重试。

## 五、方向选择中的问题与修正

### 5.1 环线内外环

408 外环路的首末站都是“二七路二七横路”，只靠首末站无法区分内外环。第一版误选了“408路内环”，加入“内环/外环后缀匹配”后，正确选择“408路外环”，站名重合度从 57.5% 提升到 93.9%。

### 5.2 时段变体

鄂101 路存在“15点30之后”的时段变体。第一版按站名重合度选中了变体，但公共线路的正式首末站更匹配常规方向。提高首末站权重并惩罚未在公共线路名中出现的时段变体后，正确选择“鄂101路(武珞路大东门--楚藩大道华容)”。

### 5.3 公共数据与高德数据的差异

部分线路站名重合度较低：

- H89：36.9%
- 402：31.1%
- 910：32.4%
- 鄂101：49.4%

这主要不是匹配算法错误，而是公共数据为 2020 年版本，高德为当前版本：

- 首末站改名或延伸；
- 线路调整、增站、撤站；
- 存在区间车、时段车、内外环等变体；
- 同名站的不同写法。

因此建议：

```text
高德返回：当前线路拓扑、站点坐标、站序（用于分析和网页展示）
公共数据：线路清单、历史对照、课程数据来源说明
匹配依据：线路号 + 方向 + 站序，不要求站名完全一致
```

## 六、实际配额消耗

控制台显示的调用量与脚本记录一致：

| 接口 | 已用 | 日配额 | 说明 |
|---|---:|---:|---|
| 关键字搜索 `place/text` | 31 | 以控制台为准，常见基础搜索 5000/日 | 10 条试点 29 次 + 前期探测 2 次 |
| 公交站 ID 查询 `bus/stopid` | 11 | 10000 | 10 条试点 10 次 + 前期探测 1 次 |
| 公交线路 ID 查询 `bus/lineid` | 19 | 5000 | 10 条试点 18 次 + 前期探测 1 次 |
| 公交线路关键字 `bus/linename` | 1 | 100 | 仅最初 340 路验证使用；10 条批量链路未使用 |

关键点：

- 10 条批量试点没有依赖 100 次/日的 `bus/linename`；
- `place/text` 属于基础搜索，不是公交线路关键字查询；
- 若关键字搜索配额为 5000/日，全量 694 条约需 2013 次，约占 40%；
- `bus/stopid` 和 `bus/lineid` 的消耗远低于日配额。

## 九、结论与下一步

试点证明该链路可以稳定批量执行：

1. POI 搜索能按线路号发现沿线公交站；
2. `stopid` 能补齐线路 ID；
3. `lineid` 能返回权威站序和坐标；
4. GCJ-02 → WGS84 → OSM 吸附误差在 15 米以内；
5. 缓存和 QPS 退避可以支持全量运行。

下一步建议：

1. 确认高德控制台中 `place/text`、`stopid`、`lineid` 的每日配额；
2. 先跑 50–100 条线路，检查低重合度线路是否需要人工规则；
3. 全量抓取 694 条线路并按站点 ID 去重；
4. 构建公交相邻站边、同站换乘边和步行接驳边；
5. 再接入 OSM 步行网络，计算 15/30/45 分钟个性化等时圈。
